在写 2026 新版 Valaxy 建站教程时，原本只想写一篇新手向纯文字攻略，写着写着却顺手把路线图、环境清单、脚手架终端、配置实验室、热更新对比和部署流水线做成了直接嵌在正文里的交互组件。做完之后忽然意识到：这本身就是「AI 时代，个人博客还有什么新玩法」的一个挺实在的答案。

## 待写提纲

### 1. 门槛反转：过去太贵，现在人人玩得起

- [ ] 以前很羡慕 Distill、Explorable Explanations 那类交互式文章，但自己写博客时，调试状态、暗黑模式和移动端适配的时间常常是写文字的几倍，大多数想法只好作罢。
- [ ] 现在纯文字总结反而越来越容易由 AI 生成，而写一个轻量 Vue 组件丢进 `components/` 的门槛却明显降低了。
- [ ] 作者和 AI 的分工变化：人负责想清楚「想让读者亲手摸到哪个概念」，实现细节与边界测试交给 AI 搭把手。

### 2. 为什么做交互式文章，反而是现代静态博客更占优势？

- [ ] **先破除一个名字上的误解**：「静态」说的是服务端无状态（不靠后端现炒现拼），不是页面只能像白纸一样不动——就像提前印好、却藏着各种翻折机关的「立体绘本」。
- [ ] **文章与组件走同一条前端构建管线，零胶水成本**：对比传统动态博客「正文在数据库富文本里，想加交互只能挂后台插件或硬塞 `iframe`」的割裂感，Valaxy 直接把 `.md` 编进 Vue/Vite 工程，组件导入、UnoCSS、Design Token、热更新和 Playwright 回归测试全在一条流里跑通。
- [ ] **文件即源码，天然适配 Git 与 AI 协作**：正文（`pages/posts/*.md`）、组件（`components/*.vue`）和样式（`styles/`）都是同仓库里的纯文本，AI 能同时看懂文章语境与主题变量，改完毫秒级预览，还能用 Git 随时回退。
- [ ] **首屏预渲染 + 浏览器端交互，性能与成本兼得**：交互都在读者端运行，不养后端进程，上线可零成本丢给 CDN / 静态托管，同时保留完整 HTML 与 `llms.txt`。
- [ ] **客观写明分工边界**：客户端交互 / 概念演示 / 可视化实验归静态构建；评论、点赞计数、在线后台等跨访客持久化数据，则通过 Waline 或 Serverless 服务来补齐。

### 3. 克制比炫技重要：怎么让交互长得像文章的一部分

- [ ] 从「套壳小卡片」到「像书籍插图一样嵌入正文」的审美复盘：
  - 统一复用站点 Design Token、`figure` / `figcaption` 与 `.yun-card-actions`，去掉卡片套卡片和多重边框。
  - 代码演示直接采用真实 Shiki 双主题配色，做「代码即控件」而不另造一套假表单。
  - 控制材质层次与动效克制（支持 `prefers-reduced-motion`），避免花哨的自动轮播抢走阅读注意力。
  - 把最容易抽象的概念做成即时对照：比如 `Ctrl / ⌘ + S` 热更新保留状态 vs 整页刷新清零、子路径忘了配 `vite.base` 后的无样式 404 效果。

### 4. 双轨博客：给人把玩，也给 AI 读

- [ ] 表面层（给人看）：Markdown + Vue 组件组成的互动实验场与小玩具箱。
- [ ] 语义层（给 AI 读）：干净的 Markdown 原文、精确的 `frontmatter`、`AGENTS.md`、`llms.txt` 与只读 MCP 巡检。
- [ ] 回归个人小站的初衷：记录之外，更是一个可以自由试验的新媒介。

### 5. 尾声方向（温暖收束）

- [ ] 技术栈会一轮轮更新，但个人博客之所以动人，从来都是作者多花的那一点偏心与诚意——把自己在意的体验做成读者伸手就能碰到的「小机关」：干净的文字留给时间与 AI，这份想让人多试两下的小浪漫，留给每一个路过的朋友。
